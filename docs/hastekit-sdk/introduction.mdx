The HasteKit Go SDK provides three layers you can use independently:

| Layer | Use it when you need | Main API |
|---|---|---|
| Model calls | Direct control over requests, messages, and response events | `NewLLMClient`, `client.Model` |
| Agents | A model that selects tools and continues until it answers or pauses | `NewAgent`, `agent.Run`, `agent.Execute` |
| Workflows | An explicit graph with application-defined routing and checkpoints | `workflow.NewGraph`, `workflow.LoadYAML` |

The SDK runs inside your Go application. A separately deployed HasteKit AI Gateway is optional; it is not required to call a provider directly or run an agent.

## Start with a working agent

Follow the [installation and quickstart](/hastekit-sdk/setting-up), then add [function tools](/hastekit-sdk/agents/tools/function-tools) or [MCP tools](/hastekit-sdk/agents/tools/mcp-tools). Use [Run and stream](/hastekit-sdk/agents/simple-agent) to choose the execution and cancellation behavior your application needs.

## Build an application

- **Conversation state:** store messages and continue a thread with [history](/hastekit-sdk/agents/conversations/history).
- **Human decisions:** require approval or collect form input with [interruptions](/hastekit-sdk/agents/tools/human-in-the-loop).
- **HTTP and UI:** expose agents through [AG-UI](/hastekit-sdk/agents/serving-agents/serving-agents-agui), including the embedded chat UI.
- **Files:** keep uploaded and generated media in [attachment storage](/hastekit-sdk/agents/attachments).
- **Durable agents:** run with [Temporal](/hastekit-sdk/agents/durable/temporal) or [Restate](/hastekit-sdk/agents/durable/restate).
- **Explicit orchestration:** build [workflows](/hastekit-sdk/workflows/introduction) in Go or YAML, then invoke them directly or expose them as tools.

## Read examples correctly

These guides describe the current SDK source. Pin the module version in your application and use documentation that matches that version. Examples use the root package with the alias `hastekit`; lower-level types live under `pkg/agents`, `pkg/gateway`, and `pkg/workflow`.

Complete programs include `package main` and imports. Smaller snippets state the variables they assume and belong inside an application function unless they declare types or methods. Provider model IDs in examples are illustrative: configure a model available to your account that supports the requested capability.

A unified request shape does not mean every provider supports every field or tool. Consult the relevant feature guide before switching providers.
