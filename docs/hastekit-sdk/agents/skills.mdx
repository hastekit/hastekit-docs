---
title: "Skills"
description: "Advertise reusable instructions and read them through one skill tool."
---

A skill is a folder containing `SKILL.md` and optional supporting resources. Its name and description help the model decide when to read it; the full instructions enter the conversation only when the model requests them.

## Write a skill

Create `skills/release-notes/SKILL.md`:

```markdown
---
name: release-notes
description: Write release notes from a set of reviewed changes.
---

Group changes into features, fixes, and compatibility notes.
Describe user-visible behavior and include migration steps when needed.
```

Keep credentials and private configuration out of skill resources. Skill text guides the model but does not enforce tool permissions.

## Configure the provider

With `model` already configured, import `pkg/agents/prompts`:

```go
skills, err := hastekit.NewSkillRegistryFromDir("./skills")
if err != nil { return err }
agent, err := hastekit.NewAgent(&hastekit.AgentConfig{
    Name: "release-assistant",
    LLM: model,
    Skills: skills,
    Instruction: hastekit.NewPrompt("Help prepare release notes.",
        prompts.WithResolver(prompts.DefaultResolvers()...)),
})
if err != nil { return err }
_ = agent
```

Setting `Skills` adds the provider's reader tool. Enabling `ResolveSkills` advertises the catalog in the prompt. Both are needed for the usual discovery-and-read experience; do not separately add a second `read_skill` tool.

## Read instructions and resources

The built-in reader accepts `{"name":"release-notes"}` for instructions and `{"name":"release-notes","file":"references/style.md"}` for a bundled resource. Resource paths must be in the registry's resource list. Reading a script returns its contents; the skill reader does not execute it.

Names must be unique across all configured sources. `NewSkillRegistryFromDir` accepts multiple directories. `NewSkillRegistry` accepts `fs.FS` sources, including an `embed.FS`, so instructions can ship with a binary.

The catalog is built at construction and is read-only afterwards. Rebuild the provider to pick up catalog changes; this is not a live registry with runtime enable/disable controls.

## Custom sources

Implement `agents.SkillProvider` with `Skills() []Skill`, `SkillTool() Tool`, and `SkillHint() string`. The provider owns the explanation of how its instructions are read. Return a nil tool only when another configured tool already provides that access.

`SkillList` advertises a list without adding a reader; `SkillsWithHint` adds host-defined guidance, for example when instructions are already mounted in a sandbox. Do not advertise a reader the agent has not been given.

A persistent dynamic skill registry and per-run skill selection are not currently built-in features.
