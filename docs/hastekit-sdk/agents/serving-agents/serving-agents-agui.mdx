The AG-UI handler exposes registered agents through HTTP and server-sent events. The embedded chat client uses the same endpoints; you can also bring your own AG-UI client.

## Mount the embedded UI

With `agent` constructed, import `github.com/hastekit/agent-sdk-go/pkg/agui/web`:

```go
registry := hastekit.NewRegistry()
if err := registry.Register(agent); err != nil { return err }
server := &http.Server{
    Addr: ":8080",
    Handler: web.Handler(registry),
    ReadHeaderTimeout: 5 * time.Second,
}
return server.ListenAndServe()
```

The UI is served at `/`, with a basic fallback at `/basic.html`. API routes are mounted under `/api/agui`. Static assets are embedded in the binary, so applications importing the package do not need to build the frontend themselves.

For endpoints without the UI, use `agui.NewHandler(registry)`. The route table below is relative to that handler; prepend `/api/agui` when using `web.Handler`.

| Method | Path | Purpose |
|---|---|---|
| GET | `/agents` | Agent names and handler capabilities |
| POST | `/agents/{agent}/run` | Start a run, or deliver a message to an active thread |
| POST | `/agents/{agent}/stop` | Stop the resolved thread's active run |
| GET | `/agents/{agent}/threads` | List stored threads |
| GET | `/agents/{agent}/threads/{thread}/messages` | Read a page of history |
| GET | `/agents/{agent}/threads/{thread}/stream` | Replay and follow a thread stream |
| GET | `/agents/{agent}/runs` | Run lifecycle event feed |

## Resolve a namespace

All namespace-scoped operations use one namespace resolved from the request. Configure `agui.WithNamespaceResolver` on the protocol or embedded handler. The resolver should read identity already established by your authentication layer; it must be safe for concurrent requests.

A nil resolver, or a blank result, selects `default`. A resolver error returns HTTP 403. There is no `WithNamespace` option and no additional cross-namespace authorization callback. A request cannot opt into another namespace by choosing a thread or stream ID.

The embedded UI needs no namespace selector and can use `default`. For a tenant-aware deployment, resolve the tenant server-side from the authenticated request. Namespace partitioning does not itself authenticate users or restrict which registered agent names they may use.

## Start and stop

A minimal AG-UI run body is:

```json
{
  "threadId": "thread-42",
  "messages": [{"id": "message-1", "role": "user", "content": "Hello"}]
}
```

`runId` is optional. The handler returns `X-Agui-Run-Id`, `X-Agui-Thread-Id`, and `X-Stream-Id` when starting a stream. For cross-origin clients, expose the headers through your CORS policy if JavaScript needs to read them.

With SDK history enabled, post the new trailing turn. `WithFullHistory()` is for a client that is the source of truth for history; using it with persisted history duplicates prior turns.

To stop, POST `{"threadId":"thread-42"}` to the stop route. An optional `streamId` must match that thread in the resolved namespace. HTTP 202 means the stop was recorded, not that every external side effect has been reversed. A new message posted to a thread already running is queued and returns HTTP 204; keep reading its existing stream.

## Reconnect without duplicating events

Record the SSE `id` of the last successfully processed event. Rejoin the thread's stream with `Last-Event-ID: <id>`, or the `lastEventId` query parameter. The server resumes strictly after that event, then follows live events.

Without a cursor, the endpoint replays the retained run from its opening event, including a completed run if retained. This is useful after a full reload. It is not an unlimited archive of the whole conversation; use the history endpoint for prior turns.

Invalid cursors, conflicting header/query values, and cursors for another stream return HTTP 400. A cursor whose required replay is no longer available returns HTTP 410. Reload persisted history and reconnect without the expired cursor. The embedded client handles reconnect cursors and history loading.

Shared replay and stop behavior across replicas requires a shared broker. A memory broker only knows events in its process. See [durable execution](/hastekit-sdk/agents/durable/temporal).

## Paginate history

Request `?limit=50`; the accepted range is 1–200 complete turns, with 50 as the default. Responses contain `threadId`, `messages`, `run`, `nextCursor`, and `hasMore`.

Send `cursor=<nextCursor>` to fetch older turns. Messages inside each page are chronological; prepend older pages to the UI. Treat the cursor as opaque and keep it scoped to the original namespace/thread. The `run` field describes the latest pending interruption or background work even when fetching an older page.

Thread listing requires `history.ThreadLister`; unsupported adapters return HTTP 501. Implement `history.TranscriptPageReader` for efficient database pagination.

## Deploy an SSE endpoint

Disable proxy buffering for event streams and configure idle timeouts to allow keepalives. `agui.WithKeepalive` defaults to 15 seconds. Do not apply a short blanket HTTP write timeout that cuts off valid long runs.

Use the same persistence and broker infrastructure on replicas serving the same conversations. Add [attachment storage](/hastekit-sdk/agents/attachments) to enable uploads and previews. Traces are exported through [OpenTelemetry](/hastekit-sdk/tracing); an embedded trace browser is not currently provided.
