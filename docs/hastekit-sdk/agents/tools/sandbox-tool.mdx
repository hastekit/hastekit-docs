---
title: "Sandbox tools"
description: "Run shell and file operations through a host-provided sandbox manager."
---

Sandbox tools delegate shell and file operations to an `agents/sandbox.Manager`. The SDK defines the tool integration; the configured sandbox service is responsible for provisioning and isolating the execution environment.

## Register tools

Given a configured `manager` implementing `sandbox.Manager`, import `pkg/agents/tools` and add:

```go
sandboxTools := []hastekit.Tool{
    tools.NewBashTool(manager, "your-sandbox-image", nil),
    tools.NewReadFileTool(manager, "your-sandbox-image", nil),
    tools.NewWriteFileTool(manager, "your-sandbox-image", nil),
    tools.NewDeleteFileTool(manager, "your-sandbox-image", nil),
}
```

Pass this slice as `AgentConfig.Tools`. The image is application configuration and must exist in your sandbox service. An optional environment map can supply run-context-templated values.

The SDK's `pkg/hastekitgateway.Config.NewSandboxClient` is an HTTP adapter for the HasteKit sandbox service. You can supply another implementation of the manager interface. The SDK does not start a local container simply because a sandbox tool is configured.

## Tool behavior

| Tool | Operation |
|---|---|
| `execute_bash_commands` | Run the `code` argument as shell commands |
| `read_file` | Read a file in the sandbox |
| `write_file` | Write file content |
| `delete_file` | Remove a file |

The bash tool starts from `/workspace` and records the working directory in tool state so later commands can continue there. Session identity selects the sandbox; preserve it when related calls should use the same environment.

## Deployment responsibilities

Configure filesystem boundaries, process limits, command timeouts, network access, credentials, and cleanup in the sandbox service. A model-visible tool description is not an isolation policy. Avoid injecting application-wide secrets when a scoped credential is sufficient.

Inspect command exit status and stderr in tool results. Do not assume a transport-successful tool response means the shell command succeeded. Use [approval](/hastekit-sdk/agents/tools/human-in-the-loop) or [middleware](/hastekit-sdk/agents/hooks) for sensitive operations.
