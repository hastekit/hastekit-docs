---
title: "MCP connectors"
description: "Connect remote tools with explicit transport, identity, discovery, and caching."
---

An MCP connector implements `agents.MCPToolset`. Configure it during application setup and pass it in `AgentConfig.McpServers`. During a run, the agent discovers its tools and executes selected calls through the connector.

## Connect over HTTP

With `ctx` and `model` already defined, import `pkg/agents`, `pkg/agents/mcpclient`, and `pkg/agents/prompts`:

```go
connector, err := hastekit.NewMCPClient(ctx, "issues", "https://mcp.example.com/mcp",
    mcpclient.WithTransport(mcpclient.TransportStreamableHTTP),
    mcpclient.WithToolPrefix("issues__"),
    mcpclient.WithToolFilter("search_issues", "create_issue"),
    mcpclient.WithApprovalRequiredTools("create_issue"),
)
if err != nil { return err }
agent, err := hastekit.NewAgent(&hastekit.AgentConfig{
    Name: "issue-assistant",
    LLM: model,
    Instruction: hastekit.NewPrompt("Help users investigate issues.",
        prompts.WithResolver(prompts.DefaultResolvers()...)),
    McpServers: []agents.MCPToolset{connector},
})
if err != nil { return err }
_ = agent
```

The URL is a placeholder; use your server's endpoint. Select the transport explicitly. Supported constants are `TransportStreamableHTTP`, `TransportSSE`, and `TransportStdio`; the default is SSE.

`WithToolPrefix("issues__")` exposes `search_issues` as `issues__search_issues` to the model. Include the separator in the prefix. Filters, approval lists, and deferred-tool lists always use the **server's original tool names**.

## Credentials and run context

`WithHeaders(map[string]string{"Authorization": "Bearer {{token}}"})` resolves values against `Input.RunContext`. Supply credentials from authenticated application state. They are not model arguments.

For stdio, use `WithCommand(command, args...)` and an empty endpoint. The command is fixed application configuration; `WithEnv` can template values from run context. The child process inherits the application environment plus those values. Deploy the executable and its dependencies on every worker that can execute the tool.

## Refreshing OAuth credentials

Use `mcpclient.WithCredentialProvider` when credentials must be fetched or refreshed rather than supplied as a fixed templated header. Implement `CredentialProvider.Resolve(ctx, connector, runContext)` or use `CredentialProviderFn`.

Return a `Credential` containing an `oauth2.TokenSource` and a stable `Principal`, such as a tenant/user identity. The token source is consulted for HTTP requests so expired tokens can refresh. The principal partitions pooled sessions; it must not change merely because a token rotated. Leaving it empty disables session pooling for token-source credentials. Never reuse one principal for unrelated users with different permissions.

This resolves credentials for an already-configured connector. It is not dynamic connector registration.

## Discovery failures

An unavailable MCP server is omitted from the run's available tools rather than necessarily failing the entire agent. `prompts.ResolveConnectors`, included in `DefaultResolvers`, tells the model which connectors are unavailable. Monitor discovery errors if a connector is essential to your application; an agent continuing is not evidence that every configured server was reachable.

## Schema caching

Caching requires an injected `SchemaCache` through `WithSchemaCache`. `WithCacheTTL` controls lifetime; it does not install a cache by itself. The cached data is the tool listing, not tool execution results.

| Server TTL | Local TTL | Effective lifetime |
|---|---|---|
| Positive | Positive | The smaller value |
| Positive | Zero/unset | Server TTL |
| Zero/unset | Positive | Local TTL |
| Zero/unset | Zero/unset | Bypass caching |

A listing explicitly marked public is shared under the connector name. Private listings, and listings with no cache-scope declaration, use a requester-specific key. Connector names must be unique across servers sharing a cache. Filters and prefixes are applied after lookup, so a cached listing still uses the current connector's tool selection.

Use `InvalidateToolCache(ctx, runContext)` for the connector's public and current requester keys. `InvalidateAllToolCache(ctx)` clears the injected cache, which can affect other connectors sharing it.

## Approval, forms, and progress

Use `WithApprovalRequiredTools` for actions requiring a human decision. `WithDeferredTools` delays full schema disclosure for selected tools. These controls are independent.

MCP elicitation can surface as an agent interruption. Send the returned call ID, action, and requested content through the normal [resolution flow](/hastekit-sdk/agents/tools/human-in-the-loop). Keep the saved continuation state; sending an unrelated user message is not the same as resolving the pending call.

The connector forwards server progress notifications to agent progress events and maps MCP annotations onto `agents.ToolAnnotations` for middleware inspection.

`WithDisableStandaloneSSE(true)` is available for Streamable HTTP servers that cannot provide the standalone server-to-client GET stream. Use it for that compatibility requirement rather than changing the transport globally.

The built-in connector list is configured in code. A persistent registry with per-user enable/disable controls and runtime connector resolution is not part of this API yet.
