---
title: "Agents as tools"
description: "Delegate a bounded task and return the result to the calling agent."
---

An agent tool runs a child agent and returns its answer to the parent as a tool result. The parent keeps control of the conversation and decides what to do next. Use a [handoff](/hastekit-sdk/agents/multi-agents/handoff) when the specialist should take over the run instead.

## Wrap a child agent

Given an already-created `researcher`, import `pkg/agents/tools`:

```go
researchTool := tools.NewAgentTool(
    "research",
    "Ask the research agent to investigate a topic.",
    researcher,
    tools.SubAgentContextModeIsolated,
)
```

Add `researchTool` to the parent's `AgentConfig.Tools`. Construct the child with its own model, instructions, tool permissions, and history configuration.

| Context mode | Thread behavior |
|---|---|
| `SubAgentContextModeIsolated` | The integration manages a separate child conversation for the call |
| `SubAgentContextModeNone` | The tool schema exposes an optional `thread_id` for selecting a child conversation |

An isolated thread is a conversation boundary, not a security sandbox. The child still executes with its configured tools and forwarded application context.

## Pauses and durable execution

If the child pauses, the wrapper returns the interruption through the parent and saves the continuation identifiers in tool state. Resume the parent using the standard interruption resolution flow. Keep the same child configuration available after the pause.

Register all participating agent configurations with a durable runtime before starting its workers. When returning a result to the parent, account for the additional model calls, tool calls, and token usage caused by delegation.
