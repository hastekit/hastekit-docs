---
title: "Conversation history"
description: "Persist runs, continue threads, and read complete conversation transcripts."
---

Agents use in-memory conversation history unless you provide a manager. A **thread** groups related runs; a **run** contains the user turn, model/tool messages, and execution state produced while answering it.

## Configure file-backed history

With `model` configured:

```go
conversationHistory, err := hastekit.OpenFileHistory("./data/conversations")
if err != nil { return err }
defer conversationHistory.Close()
agent, err := hastekit.NewAgent(&hastekit.AgentConfig{
    Name: "assistant", LLM: model,
    Instruction: hastekit.NewPrompt("Help the user."),
    History: conversationHistory,
})
if err != nil { return err }
_ = agent
```

Close the history after all agents and requests using it finish. Agents do not close caller-owned resources. File persistence is for a process that owns its storage directory; it is not a substitute for a shared database across independent workers.

## Continue a thread

Send each new turn with the same namespace and `ThreadID`. You do not need to resend previous messages: the history manager loads them. Omitting `PreviousRunID` follows the thread's current history; setting it chooses the earlier run from which to continue. Use a paused result's run ID when explicitly resuming that branch.

Choose thread IDs in your application before invoking the agent. A new ID starts another thread. Reusing a run ID is not a general HTTP idempotency mechanism: the persistence layer can reject a duplicate, and side effects need their own idempotency design.

## Read a transcript

Model context can be summarized or filtered. For a user-visible transcript, use `history.LoadTranscript`, or the paginated API, rather than treating the model's current message list as the full conversation.

With `manager` as your `*history.CommonConversationManager`:

```go
page, err := history.LoadTranscriptPage(ctx, manager.ConversationPersistenceAdapter,
    "tenant-123", "thread-42", history.TranscriptPageOptions{Limit: 50})
if err != nil { return err }
for _, row := range page.Rows { fmt.Println(row.RunID) }
next := page.NextBeforeRunID
_ = next
```

Pages contain complete stored turns in chronological order. Set `BeforeRunID` to `NextBeforeRunID` to fetch the next older page. An empty next value means the start of history. `Latest` carries the current thread state even when reading an older page.

## Supply database persistence

Implement `history.ConversationPersistenceAdapter`, then construct `history.NewConversationManager(adapter)`. It owns ID/time generation, message loading/saving, and summary persistence.

| Optional interface | Enables |
|---|---|
| `history.ThreadLister` | Thread enumeration for conversation pickers |
| `history.TranscriptReader` | Full transcript reads independent of model context |
| `history.TranscriptPageReader` | Bounded backend pagination |

Without native pagination, the helper loads a transcript and slices it in memory. Database implementations should use a bounded query ordered by insertion, not lexical run ID. Enforce namespace boundaries and run-ID uniqueness atomically in storage. Persist metadata and tool state as well as message text; approval and continuation depend on them.

## Message attribution

The incoming `history.Message` bundle can carry sender information. `history.WithMessageAttribution()` enables attribution prefixes when producing model context. Steering notices are enabled by default for messages delivered while a run is active; `WithoutSteeringNotices()` disables that annotation. Neither option replaces application authentication.
