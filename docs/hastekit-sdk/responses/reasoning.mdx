---
title: "Reasoning controls"
description: "Configure reasoning effort without assuming every model exposes the same controls."
---

`responses.Parameters.Reasoning` holds model-specific reasoning settings. The selected adapter translates supported values into its provider's request.

Given `model` and `ctx`:

```go
response, err := model.NewResponses(ctx, &responses.Request{
    Input: responses.InputUnion{OfString: utils.Ptr("Compare these two designs and explain the tradeoffs.")},
    Parameters: responses.Parameters{
        Reasoning: &responses.ReasoningParam{
            Effort: utils.Ptr("medium"),
            Summary: utils.Ptr("auto"),
        },
    },
})
if err != nil { return err }
_ = response
```

`Effort`, `Summary`, and `BudgetTokens` do not have universal meanings or accepted values. `BudgetTokens` is used by adapters that support an explicit reasoning budget. Choose settings supported by the actual provider/model rather than treating the Go struct as a capability list.

## Read returned reasoning

Reasoning items are separate from assistant text. A provider may return a summary, opaque/encrypted continuation content, or no reasoning output. A summary is not access to the model's full private reasoning.

When manually continuing a conversation, preserve returned reasoning items using the typed message conversion. Request `IncludableReasoningEncryptedContent` only for providers that support it. Do not turn encrypted continuation content into user-visible text.

Higher effort can increase latency and token consumption. Bound total output and request lifetime separately, and inspect provider-reported usage when available.
